07 / terpenes

Terpene Coverage Reality r022

✅ Flower / Concentrate

Terpene data present. Example: Berry Haze by Tyson 2.0 — 12 compounds, 3.95% total terpenes. Dominant: Myrcene.

❌ Ingestibles / Tinctures / Topicals / Beverages

terpene_count: null for all tested samples in these categories. Terpenes are stripped in processing.

Use terpene_count in the list response as a zero-cost null-check before fetching the detail endpoint. r022

The parse_confidence field (0.0–1.0) indicates extraction quality: ≥0.7 = usable, 0.5 = garbled/fallback needed. r025

08 / strategy

Integration Strategy r026

1

Lookup by brand

GET /v1/coas?brand=<brand>&limit=200 — paginate, match batch_number client-side. Brand must be known at lookup time.

2

Hit with terpenes → skip Claude entirely

If parse_confidence ≥ 0.7 AND terpene_count > 0: fetch /v1/coas/:id, map terpenes[].value_pct to COAExtraction. Zero Claude calls. ✅

3

Hit without terpenes → auto-fetch PDF

If terpene_count is null: grab pdf_url from the record → run through existing Claude parser. Saves manual upload step even if Claude is still needed. ✅

4

Miss → existing upload flow

Brand not in dataset or brand name mismatch. Fall back to the current upload+parse route unchanged.

09 / risks

Risks

r027 — Brand filter is the only key

No batch-level or license-level server-side filter. Lookup requires exact brand name match. Client-side batch matching across potentially large result sets. Brand name in our DB may not match CheckWeedNY's brand_name exactly.

r028 — Terpene data sparse for non-flower

The terpenomics app is terpene-focused, but terpenes are null for most ingestibles, tinctures, and topicals. API lookup provides zero benefit (beyond auto-fetching the PDF URL) for those categories. Highest value for flower and concentrate SKUs.
